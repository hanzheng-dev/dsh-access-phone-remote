# 我把两个月的踩坑记录，做成了一个开源项目

> 对外发布稿。可以直接发到技术社区 / 博客。
> 发布前只需替换文末的 `<>` 占位符。

---

## 起因：想在外面用自己的电脑

我有台常开的 Windows 主机，上面跑着一些自己的服务。

问题是我人在外面的时候，够不着它。

市面上的方案我都试过：

- **远程桌面**（RustDesk / 向日葵）—— 能看屏幕，但手机操作桌面很别扭，而且我只是想发个文件、看个状态
- **网盘 / 笔记** —— 数据要过别人的服务器
- **各种云服务** —— 一样的问题：**数据不在我手里**

于是我决定自己写一个。

---

## 做出来是什么

一个跑在自己电脑上的小服务（Node.js，**零 npm 依赖**），手机通过浏览器访问它，可以：

| 能做什么 | 怎么用 |
|---|---|
| **收推送** | 电脑上的脚本 / AI 完成任务后推到手机（三级优先级，横幅 / 静默） |
| **传文件** | 手机 ↔ 电脑 双向，拖进去就行 |
| **看位置** | 搜附近、看路线（接高德，含 WGS84→GCJ02 坐标纠偏） |
| **按按钮** | 预设动作（截图、显示桌面），或者你自己加的命令 |
| **收通知** | Windows 弹通知、锁屏，都能当快捷键用 |

**关键点：**

- **零 npm 依赖** —— 只用 Node 内置模块，`git clone` 完直接 `node src/server.js`
- **数据不出门** —— 服务在你电脑上，手机上只是个网页
- **一个二维码配好** —— 启动时终端直接打印二维码，手机扫一下就连上
- **局域网自动发现** —— 同一 WiFi 下，客户端广播即可找到服务，不用记 IP

另有 Android 客户端（约 2700 行，含 WebView 壳 + 原生桥），支持常驻通知、开机自启、后台收文件。

## 但这个故事的重点不是代码

**代码部分其实不难。** 真正花时间的是**让它在真实环境里跑起来**。

举几个我踩过的坑（现在文档里记了 **80 条**）：

**① 手机能 ping 通 IP，但打不开任何网页**

排查了很久，最后发现是 **Tailscale 的 MagicDNS 把自己当成了 DNS 服务器**，
而它的"上游"又是"系统默认" —— 死循环。

> 关掉 Tailscale 里的「Use Tailscale DNS」就好了。
> **但这个现象看起来完全像"网络坏了"**，不像 DNS 问题。

**② 位置总是偏 500 米**

因为手机 GPS 给的是 **WGS84**，国内地图用 **GCJ02**（火星坐标）。直接混用就差这么多。

**③ 开机自启配了，但从来没生效过**

原因是 `.bat` 文件用了 **LF 换行**（不是 CRLF）—— `cmd.exe` 解析错乱，
第一条命令就失败，**整个脚本静默失效**。

**④ 用无头浏览器截图验收，结果被误导**

用 `--window-size=400` 截图，内容右侧被裁，看起来像"窄屏溢出"。
换 800 宽再截 —— **布局完全正常**。

> headless 的 `--window-size` 和实际渲染视口不一致。
> **验收工具的不可靠，会伪装成产品的 bug。**

**这四条有个共同点**：**它们都不在文档里，只能踩出来。**

## 所以我做了两件"不太一样"的事

### 第一件：把踩过的坑全写下来

`docs/PITFALLS.md` —— **80 条**，每条都是「**症状 → 根因 → 解法**」。

```
## P10 · MagicDNS 把自己当 DNS → 手机上不了网

**症状**：
  · ping 100.100.100.100 → 通（2ms）
  · ping 223.5.5.5 → 通（23ms）
  · ping www.baidu.com → unknown host

**根因**：手机 DNS 被设成了 Tailscale 自己，而它的上游也是"系统默认" → 死循环

**解法**：Tailscale 应用 → 关掉「Use Tailscale DNS」

**诊断纪律**：测网络必须分开测「DNS 解析」和「IP 可达」
```

**这份东西别人抄不走** —— 因为它不是查文档能查到的。

### 第二件：把文档写给 AI 读

这个想法来自一个观察：**很多人装不上开源项目，不是因为他笨，是因为文档太烂。**

我的做法是：除了给人读的 README，再写一份**专门给 AI 助手看的部署剧本**（`AGENTS.md`）。

它不是给人读的说明，是**给 AI 的动作剧本**：

```markdown
## 第 0 步：先搞清楚用户的场景

问你用户这三个问题（一次问一个）：

1. 「你的电脑是 Windows 吗？」
   - 是 → 继续
   - 否 → 告诉他：核心功能能跑，但"截图/显示桌面"两个指令不可用

2. 「你想用手机在外面连电脑，还是只在家里 WiFi 用？」
   - 只想在家 → 跳过 Tailscale
   - 要在外面 → 需要 Tailscale（见第 3 步）
```

**用法**：用户不需要读懂技术细节 —— **把自己的 AI 叫来，让它读这份文件，AI 带他做。**

```
装插件 → 遇到问题 → 问自己的 AI → AI 读 AGENTS.md / PITFALLS.md → 解决
```

**这样作者就不用提供支持了** —— 不是不负责，是**把支持能力交给了用户自己的 AI**。

## 顺带做的几件小事

- **手写了一个零依赖的二维码生成器**（`public/qr.js`，约 400 行）
  - 起因：原方案调第三方 API 生成二维码，**会把访问地址 + 鉴权 token 发给别人**
  - 这违背了"数据不出门"的前提，所以自己写
  - 用 Python 的 `qrcode` 标准库**逐格交叉验证**（5 用例 × 8 掩码，全 0 差异）
  - 过程中抓到一个真 bug：**漏了"对齐图案不该被掩码"**，导致 21 个格子错

- **配置化动作**：加一个按钮不用改代码，改 JSON 就行
  ```json
  { "customActions": { "enabled": true, "list": [
      { "id": "lock", "label": "锁屏", "command": "rundll32.exe user32.dll,LockWorkStation" }
  ]}}
  ```

- **环境自检**：`node src/doctor.js` —— 12 项检查 + 建议 + 下一步
- **内置帮助页**：9 个常见问题的排查步骤，用户不用翻仓库
- **发布前检查**：一条命令跑完敏感信息扫描、语法、全部测试、必填字段、工作区洁净度
  （写它的时候顺手抓到自己一个真漏洞：检查脚本把口令当"特征值"硬编码在源码里，等于把要防的东西印在门上。现在真实值放在被 gitignore 的本地清单里）
