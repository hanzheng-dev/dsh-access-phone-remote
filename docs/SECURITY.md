# 安全说明

> 面向人类读者。

---

## 一、设计前提

**这是一个"单人自用"服务**，不是多租户产品。

**核心假设**：
- 只有**一个人**（或一个家庭）用
- 服务**只在自己的网络里**可达（局域网 / Tailscale）
- 使用者**信任自己电脑上跑的东西**

**如果你要公开到公网，请先读完本文。**

---

## 二、防护措施（已实现）

### 1. 访问令牌

- 首次启动自动生成 **24 字节随机 token**（base64url）
- 存在 `.hub-token` 文件（**已在 `.gitignore` 里**）
- 访问方式：`http://<host>:<port>/?t=<token>` → 服务端种一个长期 cookie
- 之后凭 cookie 访问（带签名，防篡改）

### 2. 回环免鉴权

`127.0.0.1` / `::1` 的请求**免鉴权** —— 方便本机脚本调用。

**⚠️ 注意**：这意味着**任何能在你电脑上跑的程序**都能访问这个服务（不需要 token）。

**这是有意的设计**：本机程序已经被信任了。

### 3. 指令白名单

`/api/run` **只能执行 `commands.js` 里登记过的动作**。

手机发的是**动作名**（如 `screenshot`），不是命令字符串。**不存在"任意命令执行"。**

**⚠️ 但要注意**：白名单里的动作本身**可能很有权限**。

例如，如果 `commands.js` 里有一个"删除文件"的动作，那调用它就能删文件。

**所以审查的重点是**：`commands.js` 里每个动作**到底能干什么**。

### 4. 文件路径白名单

- `allowDirs` 限定可访问的目录
- **防路径穿越**：拦 `..`
- **防手滑**：可执行文件（`.exe/.bat/.ps1/.vbs/.msi/.apk/.jar/.dll…`）**不通过推送接口传**
- 文件名带 `密码|secret|token|credential` 的**默认拦**

### 5. 监听地址可控

`listenHost` 默认 `0.0.0.0`（所有网卡）。

**⚠️ 如果只想让 Tailscale 能访问**，把 Clash/服务绑到 Tailscale IP 上（见 `PITFALLS.md` P69）。

## 三、风险清单

| 风险 | 严重度 | 说明 | 缓解 |
|---|---|---|---|
| **token 泄露** | 🔴 高 | 泄露 = 对方能调用所有指令 | 不要截图分享 URL；定期换 token |
| **公网暴露** | 🔴 高 | 扫描器会找到并尝试 | **别做**，除非你懂 |
| **本机程序免鉴权** | 🟡 中 | 电脑上任何程序都能访问 | 只跑可信程序 |
| **指令权限过大** | 🟡 中 | 取决于 `commands.js` 内容 | 审查每个动作 |
| **无 HTTPS** | 🟡 中 | 明文传输（局域网/Tailscale 内） | 依赖 Tailscale 的加密 |
| **文件白名单过宽** | 🟡 中 | `allowDirs` 若设为根目录 | 缩小范围 |

## 四、如果你要暴露到公网

**强烈不建议。** 如果一定要：

**必须做的**：
1. **加 HTTPS**（反向代理 + Let's Encrypt，或 Cloudflare Tunnel）
2. **强化 token**（改用密码 + 会话，或接 OAuth）
3. **限制来源 IP**（防火墙白名单）
4. **审查 `commands.js`** —— 删掉所有危险动作
5. **关掉回环免鉴权**（如果你有本机不可信的进程）
6. **加速率限制**（防暴力破解）
7. **加日志审计**

**⚠️ 记住**：这个项目的设计前提是"单人 + 私网"。公网暴露 = 你自己承担风险。

## 六、为什么这个设计是"安全"的

**核心不是技术，是架构**：

```
数据留在用户自己电脑上
   ↓
没有第三方服务器
   ↓
没有"我们收集你的数据"这个问题
```

**大厂做不到这一点** —— 因为他们的商业模式建立在"数据经过他们"上。

**这是这个项目的价值所在，也是它安全性的一部分。**
