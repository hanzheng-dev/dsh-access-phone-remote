# 排障决策树

> **给 AI 助手用。** 用户报了问题，你按这里的树往下走。
> 每条都有：**判断步骤 → 命令 → 期望输出 → 分支处理**。

---

## 通用第一步：先确认是哪一层的问题

**任何"用不了"的问题，先问这三个**：

```
1. 服务端在跑吗？
   → 电脑上执行：curl http://127.0.0.1:3099/api/ping
   → 期望：{"ok":true,...}
   
2. 电脑本机能访问吗？
   → 浏览器打开：http://127.0.0.1:3099/
   → 期望：看到页面
   
3. 手机能访问吗？
   → 手机浏览器打开：http://<电脑IP>:3099/?t=<token>
```

**根据卡在哪一步，进入下面的分支**：

| 卡在 | 问题层 | 去看 |
|---|---|---|
| 第 1 步 | **服务端问题** | § A |
| 第 1 步过、第 2 步卡 | **服务本机问题** | § A |
| 前两步过、第 3 步卡 | **网络问题** | § B |

---

## § A · 服务端问题

### A1 · 服务起不来

**症状**：`node src/server.js` 报错

| 报错 | 原因 | 解法 |
|---|---|---|
| `EADDRINUSE` | 端口被占 | 改端口（见下），或关掉占用的进程 |
| `Cannot find module './config'` | 目录不对 | 确认在项目根目录运行 |
| `Cannot find module 'xxx'` | 缺依赖 | 本项目**零依赖**，检查是不是 node_modules 缺失（不应该有） |
| 其他 | 收集完整报错问用户 | — |

**判断端口是否被占**：
```bash
# Windows
netstat -ano | findstr :3099
# Linux/Mac
lsof -i :3099
```

### A2 · 服务起来了但 ping 不通

**症状**：`node src/server.js` 没报错，但 `curl 127.0.0.1:3099/api/ping` 失败

**可能原因**：
1. **服务已崩溃** → 看终端有没有输出
2. **监听地址不对** → 检查 `config.json` 的 `listenHost`（应该是 `0.0.0.0` 或 `127.0.0.1`）
3. **端口写错了** → 看启动日志里的端口

**⚠️ 相关坑**：P52（服务没对外监听）

### A3 · 服务一会就没了

**症状**：起的时候好好的，过一会儿就没了

**根因（最常见）**：**进程挂在终端会话下，终端一关就死**

**解法**：
- **不要**用 `start` / `nohup` / 直接后台运行
- **用 Windows 计划任务**（`schtasks`）
- **⚠️ 相关坑**：P31（进程树）、P46（常驻进程必须用计划任务）

### A4 · 开机不自动启动

**排查顺序**：
1. 任务是"已启用"吗？`schtasks /Query /TN <任务名> /V`
2. `LastTaskResult` 是多少？（0 = 成功）
3. **任务是 `.bat` 吗？是的话检查换行符** → **⚠️ 坑 P32**
4. 日志文件生成了吗？（如果没生成，说明脚本压根没跑）

**⚠️ 最经典的坑**：**`.bat` 用 LF 换行 → 整个脚本静默失效**（P32）

## § B · 网络问题

### B0 · 先确定连接方式

**问用户**：你是用**局域网**还是 **Tailscale**？

---

### B1 · 局域网场景

**症状**：手机打不开 `http://192.168.x.x:3099`

**排查顺序**：

**第 1 步：手机和电脑在同一个 WiFi 吗？**
- 让用户手机上看 WiFi 名字，和电脑对比

**第 2 步：手机能 ping 通电脑吗？**
```bash
# 手机上下载 ping 工具，或直接用浏览器试
http://192.168.x.x:3099/api/ping
```

**第 3 步：如果 ping 都不通 → 防火墙问题**

**⚠️ 判断特征**：**局域网不通但 Tailscale 通 = 防火墙问题**（坑 P53）

**解法**（Windows，管理员）：
```bash
netsh advfirewall firewall add rule name="dsj" dir=in action=allow protocol=TCP localport=3099
```

**另外检查**：Windows 网络位置是不是「公用」？（公用会拦所有入站）→ 坑 P53

---

### B2 · Tailscale 场景

**症状**：用 `http://100.x.x.x:3099` 打不开

**排查顺序**：

**第 1 步：两边都装了 Tailscale 并登录同一账号吗？**
```bash
tailscale status
```
**期望**：能看到对方设备

**第 2 步：能 ping 通 Tailscale IP 吗？**
```bash
ping 100.x.x.x
```

**第 3 步：⚠️ 如果 ping 通但打不开网页 → 可能是 DNS 问题**

**⚠️ 经典的坑 P10**：Tailscale MagicDNS 抢 DNS
- **症状**：能 ping 通 IP，但打不开任何域名
- **判断**：让用户手机 ping 一个域名试试
- **解法**：Tailscale 应用里**关掉「Use Tailscale DNS」**

**第 4 步：刚切换网络吗？**
- **⚠️ 坑 P12**：刚切网有 1-2 分钟窗口，这期间走中继、很慢
- **解法**：等 1-2 分钟

---

### B3 · 能连但很慢

**排查**：

| 情况 | 原因 | 解法 |
|---|---|---|
| 刚切网 | 走中继（DERP） | 等 1-2 分钟（坑 P12） |
| 一直慢 | 移动网本来就慢 | 局域网 19.9 MB/s vs 移动网 0.7 MB/s（坑 P13） |
| 传大量小文件 | 每文件多次往返 | 打包再传（坑 P59） |
| 局域网能用却走隧道 | 没优先局域网 | 检查连接地址（坑 P60） |

**判断是否走中继**：
```bash
tailscale ping <对方IP>
```
- 显示 `via DERP` → 走中继（慢）
- 显示 `via <IP>:<port>` → 直连（快）

---

### B4 · 过一会儿连不上

**症状**：刚连上没问题，过几分钟/几小时就连不上

**根因（按概率）**：

1. **手机后台被杀**（最常见）
   - **解法**：Tailscale 加进电池白名单 + 开启常驻 VPN → 坑 P14
2. **Tailscale 被杀**
   - **检查**：`tailscale status`
   - **⚠️ 坑 P11**：白名单式杀进程可能把 Tailscale 杀了
3. **adb 掉了**（如果用 adb）
   - **解法**：`adb disconnect` + `adb connect`

## § C · 功能问题

### C1 · 收不到推送

**排查顺序**：

**第 1 步：服务端发出去了吗？**
```bash
curl -X POST http://127.0.0.1:3099/api/push \
  -H "Content-Type: application/json" \
  -H "x-auth: <token>" \
  -d '{"text":"测试"}'
```

**第 2 步：页面收到了吗？**
- 打开页面看有没有这条消息

**第 3 步：⚠️ APK 后台收不到 → SSE 读超时**
- **⚠️ 坑 P29**：`setReadTimeout(0)` 导致连接静默变半死
- **判断**：看 logcat 有没有「距上次收数据 xxx ms」
- **解法**：改成 45000ms

**第 4 步：⚠️ Android 13+ 通知权限**
- **⚠️ 坑 P54**：光在 manifest 写权限不够，**必须主动调 `requestPermissions()`**

---

### C2 · 位置不准 / 偏 500 米

**⚠️ 这是最经典的坑 P15**

**判断**：
- 偏差在 **几百米级别** → **坐标系问题**（WGS84 vs GCJ02）

**解法**：
- 确保定位后**转成 GCJ02** 再调高德
- 高德返回的坐标**本身就是 GCJ02**，直接用

**排查命令**：
```bash
# 看服务端拿到的坐标
curl http://127.0.0.1:3099/api/loc
```
- 如果只有 `lat/lng`（WGS84）没有 `gcjLat/gcjLng` → 转换没做

---

### C3 · 位置功能报 `INVALID_USER_KEY`

**根因**：高德 key 的 referer/域名限制（坑 P17）

**解法**：
1. 去高德控制台
2. 把域名加白，**或留空 = 不限**
3. 注意：**Web服务 key 和 JS API key 是两个不同的 key**

---

### C4 · 传文件报错

**排查**：

| 报错 | 原因 | 解法 |
|---|---|---|
| 路径不在白名单 | `allowDirs` 不含该目录 | 让用户在 `config.json` 加 |
| 文件太大 | 超过上限 | 上传限 20MB，读限 2MB |
| 可执行文件被拒 | 安全策略 | **这是故意的**（坑 P46） |
| 文件名含敏感词 | 安全策略 | **这是故意的** |

---

### C5 · 截图 / 显示桌面用不了

**根因**：**这两个功能是 Windows-only**（依赖 PowerShell + Win32）

**解法**：
- Windows 用户：检查 PowerShell 可用性
- **非 Windows**：告诉他这两个功能本来就不支持

**⚠️ 如果报权限错误**：可能需要管理员权限（坑 P51）

## § D · 编译 / 构建问题（如果要改 APK）

### D1 · `d8` 报 NullPointerException

**⚠️ 坑 P24 —— 这是最坑的**

**症状**：
```
java.lang.NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null
   at com.android.tools.r8.graph.u2.<init>
```

**根因**：**JDK 24 + 匿名内部类**

**解法**：**源码里一个匿名内部类都不留**，全改具名嵌套类

---

### D2 · Windows 工具路径报错

**⚠️ 坑 P25**：`aapt2` / `javac` / `d8` / `7z` 不认 MSYS 的 `/d/...`

**解法**：转成 `D:/...`；**这时加 `MSYS_NO_PATHCONV=1` 反而坏事**

## § E · 完全没见过的错

**你的处理流程**：

1. **先查 `docs/PITFALLS.md`**（87 条，覆盖绝大部分）
2. **再查本文的决策树**
3. **还是不行 → 要用户提供**：
   - 完整报错文本
   - 他做了什么操作
   - 环境（系统版本、Node 版本、手机型号）
4. **如实告诉用户**：
   > 「这个我不确定。项目文档里没覆盖。
   > 你可以去 GitHub 提 issue，附上上面的信息。」

**⚠️ 绝对不要编造解决方案。** 编一个错的，比说"不知道"伤害大得多。
