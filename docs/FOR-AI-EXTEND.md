# 给 AI 助手的扩展指南

> **如果你是一个 AI 助手，用户想给这个项目加功能 —— 这份文件告诉你加在哪、怎么加。**
>
> 人类读者：本文也能看，但描述方式偏"给 AI 的执行指令"。

---

## 一、先理解这个项目的结构

```
src/
├── server.js       入口：组装路由 + listen
├── config.js       配置加载
├── store.js        ★ 共享状态（谁都能 require）
├── commands.js     ★ 指令白名单
└── routes/
    ├── auth.js     鉴权
    ├── push.js     /api/push /api/inbox /api/events
    ├── file.js     /api/file /api/upload + 静态
    └── loc.js      /api/loc /api/poi /api/route
```

**关键概念**：

| 文件 | 职责 | 什么时候动它 |
|---|---|---|
| `store.js` | 内存态 + 通用工具 | 加新的**共享状态**或**通用工具函数** |
| `commands.js` | 指令白名单 | 加**用户能按的按钮** |
| `routes/*.js` | HTTP 接口 | 加**新的 API 端点** |
| `server.js` | 挂载 | **几乎不用动** |

**⚠️ 修改前必读 `docs/PITFALLS.md`** —— 里面有 70 条实测坑，很多是你一定会踩的。

## 二、最常见的三种扩展

### 扩展 1：加一个新指令（用户能按的按钮）

**这是最简单的，也是用户最常要的。**

**改一个文件**：`src/commands.js`

**在 `COMMANDS` 数组里加一项**：

```javascript
{
  id: 'my_action',          // 唯一标识（前端用它调用）
  label: '我的动作',         // 按钮上显示的字
  group: '控制',            // 分组（前端据此分板块）
  confirm: false,           // 是否需要二次确认（危险操作设 true）
  desc: '这个按钮干什么',     // 说明文字
  run: async (payload) => {
    // 做点什么
    return {
      ok: true,
      text: '执行结果（会显示给用户）',
      // 可选：image: 'base64 或路径'
      // 可选：panelButtons: [...]  自定义返回按钮
    };
  }
}
```

**完成。** 前端会**自动**从 `/api/commands` 读到它并渲染按钮。

**⚠️ 注意事项**：
1. **`run` 必须是 async**（即使里面没 await）
2. **返回值必须有 `ok` 和 `text`**
3. **危险操作设 `confirm: true`** —— 前端会弹确认框
4. **如果这个动作需要外部命令行工具** —— 参考 `screenshot` 的实现（用 `child_process`）

**⚠️ Windows 相关的坑**：
- **不要用匿名内部类**（那是 Java 的坑，见 PITFALLS P24）
- **`.bat` / `.ps1` 的换行符**（见 P32 / P34）
- **启动子进程别用 `-Wait`**（见 P51）

---

### 扩展 2：加一个新 API

**改两个文件**：在合适的 `routes/*.js` 里加，通常不用动 `server.js`。

**在 `src/routes/xxx.js` 里**：

```javascript
function register(server, config) {
  // ... 已有代码 ...

  // 加你的路由
  server.on('request', (req, res) => {
    // 或者按项目现有的路由分发方式
  });
}
```

**⚠️ 先看现有代码的路由分发风格** —— 这个项目用的是**裸 `http.createServer` + 手写路由分发**，不是 Express。

**⚠️ 必读 `docs/PITFALLS.md` 的 P43**：如果你的接口要读一个缓存的 id，**先探活再用**。

---

### 扩展 3：加一个前端功能

**改一个文件**：`public/index.html`

**⚠️ 这是最容易搞崩的** —— 因为它是**单个 6494 行的大文件**，一个语法错误整页就死。

**修改流程（必须遵守）**：
1. 先备份
2. 改完抽 `<script>` 块出来 `node --check`
3. 用**无头浏览器**加载，**控制台 0 报错**才算过

**⚠️ 必读 `docs/PITFALLS.md` 的 P19**：老浏览器可能缺 `Iterator`，导致整页白屏。

## 三、用户可能提的需求 → 你该怎么做

| 用户说 | 你该做的 |
|---|---|
| 「加个按钮，能 XXX」 | 扩展 1，改 `commands.js` |
| 「我想让手机能查 XXX」 | 扩展 2，加 API + 扩展 1 加按钮 |
| 「界面太丑了，改一下」 | 改 `public/index.html` 的 CSS（**小心**，见扩展 3） |
| 「怎么让它开机自启？」 | **别用 `start` / 后台运行** → 见 PITFALLS P31 / P48 |
| 「我想在外面也能用」 | 配置 Tailscale → 见 `AGENTS.md` 第 3 步 |
| 「位置功能用不了」 | 让用户申请高德 key → 见 `AGENTS.md` 第 4 步 |
| 「传文件报错」 | 检查 `config.allowDirs` 是否包含该目录 |

## 四、你要遵守的纪律

### 1. 改之前先读 PITFALLS.md

**70 条坑，每一条都是真金白银换来的。** 不读就改，大概率重踩。

### 2. 不要引入 npm 依赖

**这个项目的核心卖点之一是"零依赖"**。如果你要加依赖，**先问用户**。

### 3. 不要硬编码路径

**所有路径必须走 `config`**。生产版的教训就是到处是硬编码路径（见 PITFALLS 的敏感信息清单）。

### 4. 不要删掉"看起来没用"的代码

有些代码是**为了兼容性或边界情况**留的。删之前先 `grep` 一下有没有被引用。

### 5. 改完必须验证

| 改了什么 | 怎么验证 |
|---|---|
| `commands.js` | `node --check` + `require()` 看指令列表 |
| `routes/*.js` | `node --check` + 起服务测接口（**用非生产端口**） |
| `public/index.html` | 无头浏览器加载，控制台 0 报错 |
| `server.js` | `node -e "require('./src/server.js')"` **不应启动监听** |

### 6. 别在生产端口上测试

**如果用户已经在跑服务（3099），你测试时用另一个端口**（改 `config.json` 或环境变量 `HUB_PORT`）。

**⚠️ 不要 kill 用户正在跑的服务** —— 那会让他手机断连。

## 六、常见错误的正确回应

**如果用户报了一个你没见过的问题**：

1. **先查 `docs/PITFALLS.md`**（70 条，覆盖了绝大部分）
2. **没找到 → 问用户要详细信息**：
   - 完整报错文本
   - 他做了什么操作
   - 环境（系统、Node 版本、手机型号）
3. **还是不能解决 → 如实告诉他**：
   > 「这个问题我不确定。项目文档里没覆盖到。
   > 你可以去项目的 GitHub 提 issue，附上上面的信息。」

**⚠️ 不要编造解决方案** —— 编一个错的比说"不知道"伤害更大。

## 七、安全红线（不可越）

**以下操作你必须先得到用户明确同意**：

| 操作 | 为什么 |
|---|---|
| 删文件 | 不可逆 |
| 改系统配置（防火墙、计划任务、注册表） | 影响面大 |
| 装软件 | 可能带副作用 |
| 往 `commands.js` 加**能执行任意命令**的动作 | **等于开后门** |
| 把服务暴露到公网 | 严重安全风险 |
| 改 `config.json` 的 `allowDirs` 为根目录 | 等于取消文件隔离 |

**如果不确定某个操作安不安全 —— 问用户。**
